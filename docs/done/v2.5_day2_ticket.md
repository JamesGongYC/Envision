### Track B pre-decided

**Inherited from Day 1:** `LayerVisibilityContext` provides toggle state; `LAYER_TREE` defines what's available; placeholder layers render as disabled checkboxes.

**New for Track B Day 2:**

1. **Server-side bbox-filtered queries.** Signal layer queries return GeoJSON FeatureCollections filtered by current map bounds. Each query is keyed by `(source, signal_type, bbox)` and returns up to N features. Server component fetches on initial render; client component refetches on map pan/zoom via an API route.

2. **API route for dynamic refetch.** Map pan/zoom is client-side interaction; ISR doesn't apply. Add `viewer/app/api/signals/route.ts` that accepts bbox + layer-id query params and returns GeoJSON. Map pan handler calls this route with debouncing.

3. **Per-layer max-points cap = 5000.** If a query would return >5000 points (FIRMS global, especially), apply random sampling. Surface the cap to operator via a small "(showing 5000 of 12,847)" subtitle on the layer's marker count.

4. **Marker clustering for FIRMS and other dense layers.** Use `leaflet.markercluster`. Apply only to layers where `expected_density > 50_markers_per_zoom`. For sparse layers (NHC, JTWC), render individual markers directly — clustering would be visual noise.

5. **Per-signal-type visual treatment.** Define in `viewer/lib/signal-styling.ts`:

   | signal_type | color | shape | radius | opacity |
   |---|---|---|---|---|
   | `hotspot` (FIRMS) | red | circle | 3px | 0.6 |
   | `fire_warning` (NWS) | orange | circle | 5px | 0.8 |
   | `cyclone_advisory` (NHC) | blue | square | 8px | 0.9 |
   | `cyclone_advisory` (JTWC) | indigo | square | 8px | 0.9 |
   | `cyclone_feature` (AIFS) | cyan | diamond | 6px | 0.7 |
   | `fire_weather` (Open-Meteo) | amber | circle | 4px | 0.6 |
   | GDACS ground truth | gray | cross | 6px | 0.5 |

   Differentiate NHC vs JTWC by color (operational source matters). Differentiate AIFS cyclone features (model prediction, cyan = lower confidence visual cue) from NHC/JTWC (operational bulletins).

6. **Recency-based fade.** Optional polish: signals older than 12h render at 0.4 opacity, fresher signals at full opacity per the table. Single Tailwind class on the marker SVG; computed from `timestamp` field server-side.

7. **Polygon layers wait for Day 3.** Day 2 explicitly excludes ECMWF and AIFS grid polygons. Their placeholder checkboxes stay disabled until Day 3.

### Track B deliverables

#### B1 — `viewer/lib/signal-queries.ts`

Server-side query layer:

```ts
type BBox = { west: number; south: number; east: number; north: number }
type SignalQueryParams = {
  source?: string
  signal_type?: string
  bbox?: BBox
  since?: Date  // default: now() - interval '24 hours'
  limit?: number  // default: 5000
}

export async function fetchSignalsAsGeoJSON(
  params: SignalQueryParams
): Promise<GeoJSON.FeatureCollection> { ... }
```

Implementation: parameterized SQL using `ST_AsGeoJSON(geometry)` for the geometry field, payload spread into properties. Bbox filter via `ST_MakeEnvelope(...)` if provided. ORDER BY `timestamp DESC LIMIT :limit`. If result count equals limit, set a `truncated: true` flag in the FeatureCollection's metadata.

GDACS lives in `ground_truth`, not `signals` — need a parallel query or a UNION view. Simpler: add a `fetchGroundTruthAsGeoJSON` companion function.

## Notes / gotchas

**Track A:**

- **Secret recreate is destructive.** `modal secret create envision-neon ...` REPLACES the secret entirely. Missing one field bricks all dependent functions until fixed. Double-check the command includes every existing field plus the two new ones.
- **NWS User-Agent etiquette.** NWS requests reject without a valid User-Agent (some return 403, some HTML). Format: `"envision-monitor (your-email@example.com)"`. Use the same value already in `~/.hermes/.env`.
- **FIRMS row volume.** First Modal run might insert thousands of rows — that's correct, not a bug. Watch `signals` table size after this lands; tighten retention if approaching 0.4GB.
- **JTWC parser fixture.** Bring `fixtures/sample_wp.dat` into the Modal skill dir. Don't reference Hermes paths.
- **NHC pre-season empty.** 0 rows from NHC is normal in May/early June. Verify via `modal app logs nhc-cyclones` that the script ran without errors, then proceed.

**Track B:**

- **Leaflet markercluster import quirks.** `react-leaflet-cluster` doesn't have perfect SSR support; ensure it's used only inside the dynamically-imported `forecast-map-impl.tsx` (the `ssr: false` boundary).
- **Bbox encoding.** Use `bbox.toString()` as `"west,south,east,north"` for URL params. Decode in API route.
- **Map move event debouncing.** Without debouncing, every pixel of pan fires a refetch. 200–300ms debounce is reasonable; tune by feel.
- **GDACS layer separately.** GDACS lives in `ground_truth` table, not `signals`. Make sure the GDACS layer uses a different query function (`fetchGroundTruthAsGeoJSON`).
- **Marker click vs popup.** Existing forecast markers should still navigate to `/forecast/[id]` on click. Signal markers should open Leaflet popups in place. Don't cross the streams.
- **Truncation visibility.** When a query hits the 5000 cap, the operator must see this. Add a small "(5000 of 12,847)" badge near the layer's checkbox or as a subtle map overlay.
- **Color contrast for accessibility.** The proposed palette has decent contrast against CartoDB Positron tiles (light background). If you swap to dark tiles later, re-tune.
