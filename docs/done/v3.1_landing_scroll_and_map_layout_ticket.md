## Task 1 — Scroll from landing goes straight to the map (like the arrow)

Today `/` is two stacked full-height sections (hero, then Forecasts map) with free scroll; the arrow smooth-scrolls to the map. Make a **scroll gesture from the hero commit straight to the map** — same animated transition and end state as clicking the arrow, no resting partway.

- **Shared target:** extract one `scrollToMap()` (smooth `scrollIntoView` on the map section, e.g. `#forecasts`). The arrow and the scroll behavior both use it. Add a `scrollToHero()` counterpart.
- **Primary approach — CSS scroll-snap** (native, accessible, least code):
  - Make `/` a snap container: `scroll-snap-type: y mandatory; scroll-behavior: smooth;` with each section sized to the viewport **below the pinned chrome** — `height: calc(100dvh - var(--chrome))` (chrome = nav + disclaimer banner; see Task 3) and `scroll-snap-align: start;`. (Sizing to the remaining viewport, not full `100dvh`, is what keeps the banner on screen in both sections.)
  - `scroll-padding-top` = height of any sticky nav/banner so snapped sections align below global chrome.
  - A single wheel tick / swipe then animate-snaps hero → map (and back), matching the arrow.
- **Fallback** if snap fights the map: a one-shot wheel/touch/keydown interceptor on the hero that `preventDefault`s the first downward intent (`wheel deltaY`, upward swipe, or `ArrowDown`/`PageDown`/`Space`/`End`) and calls `scrollToMap()`, with a lock ref released on `scrollend`. Symmetric up-intent at map top → `scrollToHero()`.
- **Reduced motion:** gate the smooth animation behind `prefers-reduced-motion` (instant jump when reduced) for both the arrow and the scroll path.
- **Leaflet coexistence:** keep the map's `scrollWheelZoom` enabled — Leaflet owns the wheel while the pointer is over the map canvas (so zoom still works); page snap/scroll happens over the dead-zone padding introduced in Task 2. Do not let the snap container hijack wheel events over the Leaflet canvas.

**Accept:**
- [ ] A downward scroll from the hero animates straight to the map, ending exactly where the arrow lands; no partial-scroll resting state.
- [ ] Arrow still works (both use `scrollToMap()`); scrolling back up returns to the hero.
- [ ] Wheel over the map zooms the map, not the page.
- [ ] `prefers-reduced-motion` → instant jump, no animation.

## Task 2 — Box the map; move layer panel + legends above it, horizontal

Stop the full-bleed map. Render the map in a **contained box inset from the viewport**, and move the **3-layer panel and all legends out of the map into a horizontal bar above it**.

- **Boxed map** (`forecast-map.tsx` / `forecast-map-impl.tsx`): map sits in a rounded, bordered box modestly inset from the viewport edges (a bit smaller than full browser). The Forecasts section is still one viewport (`100dvh`): a control bar on top, the map box below.
- **External control/legend bar** (new `components/map-controls-bar.tsx`, or repurpose `map-layer-panel.tsx`): a single **horizontal** bar at the top of the Forecasts section, **outside the Leaflet container**:
  - Left cluster: the 3 layer toggles — **Forecasts · Detections · Atmosphere** (reads/writes the existing `LayerVisibilityProvider` state; **keep the Day-1 localStorage persistence and defaults: Forecasts+Detections ON, Atmosphere OFF**). Drop the old right-side collapsible overlay placement.
  - Right cluster: the legends — forecast probability ramp, signal-type swatches, and the wind/velocity scale — lined up horizontally. Wrap gracefully on narrow widths (desktop-first; just don't break).
- **Pull legends out of the map:** if legends currently render as in-map Leaflet controls (in `forecast-map-impl.tsx`), extract them into a plain React `components/map-legend.tsx` shown in the bar. For the velocity layer, set `displayValues: false` in `wind-layer.tsx` and show the wind legend in the bar instead of the plugin's in-map bottom-left box.
- **Keep attribution in the map** (Leaflet attribution control stays — TOS requirement; only layers/legends move out).

**Leaflet gotchas — do not skip (your documented footguns):**
- **Explicit height or the map collapses to 0.** The box needs a non-percentage height; recompute the calc for the new chrome: `height: calc(100dvh - <nav> - <banner> - <control-bar> - <box padding>)`. Percentage heights through the dynamic-import subtree fail at mount-time measurement.
- **Call `map.invalidateSize()`** after the container changes from full-bleed to boxed and on window resize, or tiles render against stale dimensions.

**Accept:**
- [ ] Map is a contained, inset, bordered box — not full-bleed.
- [ ] Layer toggles and legends sit in a horizontal bar **above** the map, outside the Leaflet container; nothing for layers/legends overlays the map.
- [ ] Toggles still drive the same 3 layers with Day-1 defaults + persistence intact.
- [ ] Map fills its box (height ≠ 0), tiles correct after load and after resize (`invalidateSize`).
- [ ] Wind legend shown in the bar; plugin's in-map legend disabled.
- [ ] Attribution still visible on the map.

## Task 3 — Keep the top banner (and nav) pinned across hero + map

The disclaimer banner is a **NEVER-CUT** item — it must remain visible on **every** view, including the Forecasts **map** section. With the snap panes from Task 1, in-flow chrome would scroll off when snapping to the map, so:

- **Pin the global top chrome** — the nav bar **and** the disclaimer banner — with `position: sticky`/`fixed` at the top so both stay visible across the hero and the map sections (and don't get consumed by a snap pane).
- Expose the combined chrome height as a CSS var (`--chrome`) used by: the snap-pane height (`calc(100dvh - var(--chrome))`, Task 1) and the map-box height (`calc(100dvh - var(--chrome) - <control-bar> - <box padding>)`, Task 2). One source of truth so nothing overlaps or hides the banner.
- The banner stays a slim strip (Day 1 restyle); don't let it grow tall enough to eat the map pane.

**Accept:**

- [ ] Nav stays visible/pinned too.
- [ ] No chrome/section/map overlap; banner doesn't cover the map or the control bar.
- [ ] Banner remains present on the other pages (regression — it's global).
