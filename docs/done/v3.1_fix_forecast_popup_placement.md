# v3.1 — Fix Ticket: Forecast popup overflows the map top as reasoning types in

**Type:** bug fix · `viewer/` only · Forecasts map popover · no backend/DB change
**Related:** the in-place forecast detail popover (`forecast-dropdown.tsx`) with typing-animated LLM reasoning (Day 1 Task 5 removed the skip button — typing stays). Must stay inside the **boxed map** introduced by `v3.1_landing_scroll_and_map_layout_ticket.md`.

---

## Symptom & cause
Clicking a forecast dot opens the detail popover **above** the dot. As the reasoning types in line-by-line, the popover grows taller; because it's anchored at the bottom (tip on the dot) it expands **only upward**, and for dots in the upper map it runs off the top edge / outside the map.

## Fix — anchor beside the dot, let it grow both directions
Re-anchor the popover to the **side** of the dot (vertically aligned to it) instead of above it, so added lines expand **up and down** rather than only up, and keep it clamped inside the map.

Behavior spec:
- **Side placement:** open to the right of the dot by default, vertically centered on it.
- **Flip:** if there isn't room on that side (dot near the right edge), flip to the left.
- **Shift / clamp:** keep the whole popover inside the **map box** (boundary = the Leaflet container / boxed map, with a few px padding). Near the top or bottom edge it shifts along the vertical axis to stay fully visible — it never leaves the map.
- **Recompute while typing:** the popover height changes every line during the animation; reposition on each content-size change so it stays beside the dot and inside the box throughout. (This is the actual fix — static positioning at open time is not enough.)
- **Reposition on map interaction:** also update placement on map pan/zoom so it tracks the dot.
- **Height guard:** set a `max-height` (≈ map box height minus padding) with internal scroll as a safety net, so even very long reasoning can't exceed the box after all collision handling.
- Optional: a small connector/caret from the popover edge pointing at the dot.

## Implementation
First determine what the popover currently is:
- **If it's a custom React floating element:** use **`@floating-ui/react`** — `placement: 'right'`, middleware `offset()`, `flip()`, `shift({ boundary: <map container el>, padding })`, `size()` (for the max-height clamp), and `autoUpdate` so it recomputes on resize/scroll/zoom. Anchor a virtual reference at the dot's screen point via `map.latLngToContainerPoint(latlng)`; update on map `move`/`zoom`. Drive a reposition on the typing content's `ResizeObserver` (autoUpdate covers most, but confirm height-change ticks fire).
- **If it's a Leaflet `L.popup`:** Leaflet popups always anchor above with the tip on the marker and can't cleanly side-anchor or grow downward — replace it with a custom floating element (above) rendered in the map container. Keep the same open/close triggers and content.
