# Envision v3.1 — Frontend Refactor (Dark / Commercial)

A pure viewer sprint. No agent, schema, or pipeline changes. Evolve the public surface from a light research dashboard to a dark, sparse, Palantir-adjacent product: a landing pitch, a clean three-layer Forecasts map, an interactive skill-lineage **Evolution** view, an interactive **About** pipeline figure, and a demoted **Disclaimer**.

> **Naming note (carry into PROGRESS):** "v3.1" already denotes the deferred **Generator + diversity penalty** in `PROGRESS_v3_addendum.md` (cut-list #1/#2). This sprint reuses the label for frontend work. Recommend renumbering the evolution backlog to **v3.2** so "what shipped in v3.1" stays unambiguous. This file is named `v3.1_frontend_plan.md` to disambiguate regardless.

---

## 1. Premise

Three jobs:

1. **Comprehension in 3 seconds.** A first-time visitor should understand what Envision *is* before scrolling — big type, a single pitch line, obvious design language.
2. **Density without clutter.** Collapse 9+ toggleable layers to 3; collapse redundant signal lists; strip explanatory prose that reads as research-hedging rather than product confidence.
3. **Make the evolution legible as a product feature.** The self-evolving skill library is the differentiator. Surface it as a live lineage graph, not a log.

Backend is untouched. Every change is in `viewer/`. The agent, Modal skills, migrations, and DB stay exactly as they are at end of `PROGRESS_v3_addendum.md`.

## 3. Commercial layer names (pick one set)

| # | Default | Contents | Option A | Option B | Option C (chosen) |
|---|---|---|---|---|---|
| 1 | ON | model forecasts | Forecasts | Risk | **Forecasts ✅** |
| 2 | ON | hotspots, fire alerts, fire-weather, fire-weather-grid, cyclone advisories, cyclone features, heavy-precip | Signals | Observations | **Detections ✅** |
| 3 | OFF | **AIFS surface-wind velocity field** (`WindLayer` / leaflet-velocity, `/api/wind`) | Wind Field | Wind | **Atmosphere ✅** |

**Atmosphere membership — LOCKED.** Layer 3 ("Atmosphere") = the old "Atmospheric flow – surface wind (AIFS + 24h)" layer only — the animated **velocity field** rendered by `wind-layer.tsx` (`leaflet-velocity`, fed by `/api/wind` from AIFS 10m surface wind). It is **not** a `signals` signal_type, so the toggle **mounts/unmounts the `WindLayer` component**, not a GeoJSON filter. No other source belongs in Layer 3. The discrete AIFS `high_wind_corridor` polygons are a *separate* artifact and stay in **Detections (layer 2)**, along with `cyclone_feature`, `fire_weather_grid`, and `heavy_precipitation_band`. (**Cursor:** Forecasts/Detections toggles map to signal_type sets in `layer-state.ts`; the Atmosphere toggle gates rendering of `<WindLayer/>`. Lazy-mount on enable — the particle layer is the heavy one.)

## 5. NEVER CUT (safety + legal — survive the redesign untouched)

These predate v3.1 and are load-bearing for the project's risk posture. The dark/commercial pass must not delete them:

1. **Persistent disclaimer banner on every page** (`envision_plan` §12; risk-table mitigation for "public misinterprets as alerting service"). May be restyled to a slim dark strip, but stays globally present and legible. Locked §12 text appears **in full** on `/disclaimer` and truncated in `<meta name="description">` + README.
2. **Source attribution** (`envision_plan` §5 / §14 — "attribution on every forecast detail page", TOS condition for FIRMS/NWS/NHC/JTWC/Open-Meteo/ECMWF/AIFS/GDACS). Signal de-dup keeps **one attribution link per source**. If the Disclaimer trim removes the sources/methodology block, that content **moves to the new About** (the Ingest panel) — it is not deleted.

If either feels like it conflicts with "less wordy," resolve by relocating, never by removing.

## 7. Data / query work (read-only; no schema change)

1. **Lineage graph query** (`lib/lineage-queries.ts`): build nodes from `skill_lineage` (skill_id, parent_skill_id, version, generation_method, status), edges from `parent_skill_id`. Per-node stats (Brier / hits / FP / misses / emitted) aggregated **from live `evaluations`**, per `(skill_id, version)`.
   - **Show live/shadow Brier, not backtest Brier.** Per addendum §3 the backtest sanity gate is unvalidated and its Brier is provisional. Public Evolution view shows trusted **live** Brier; shadow candidates render as a distinct node state ("evaluating, N/20") and must not display backtest ranking as authoritative.
   - Handle all `generation_method` (`manual|mutated|generated`) and `status` (`candidate|shadow|promoted|archived`) values; handle `lineage_id IS NULL` legacy proposals gracefully (don't crash the tree).
2. **Forecast contributing-signals de-dup:** group `contributing_signal_ids` by `source` (or `source, signal_type`); render one row per group with a count (e.g., "NASA FIRMS · 47 detections"). Reuse `signal-sources.ts` for the single per-source attribution link.
3. **About telemetry:** reuse the three facts the old `StatusHeader` computed — `last ingestion = max(timestamp) from signals` → Ingest panel; `skills active = count of active detection skills` → Forecast panel; `curator status / last proposal = max(proposed_at)` → Evolve panel.

## 8. Day-by-day roadmap (4 days + buffer)

### Day 1 — Design system + routing skeleton (foundation; everything else inherits this)
- Establish dark **monochrome** tokens (consult the **frontend-design** skill for token discipline): near-black field (~#0A0A0B), 1–2 elevated greys, off-white type, **no brand accent** — B&W everywhere except data viz. Heavy grotesk display + monospace for labels/data. Big-type scale for the hero. **Data-viz colors are unchanged** — forecast + signal layers keep their current palette (per your dark-OSM work), contrast-tuned only where needed.
- Invert/remove the v1 `prefers-color-scheme` light-forcing override in `globals.css` so the app renders dark; **dark basemap already in place (Cursor)** — just confirm layers read well on it; keep `@import "leaflet/dist/leaflet.css"`.
- Restyle `disclaimer-banner` as a slim dark strip (kept global).
- Route work: create `/evolution`, `/disclaimer`, `/how-it-works`; add redirects `/agent → /evolution` and `/about → /how-it-works`; rebuild nav (Forecasts·Evolution·About→`/how-it-works`) + footer (Disclaimer link). **Link audit:** every internal link/`<meta>` that pointed at `/about`-as-disclaimer now points at `/disclaimer`; nav "About" label points at `/how-it-works`.
- Remove `StatusHeader` from `layout.tsx` (keep `LayerVisibilityProvider`).

### Day 2 — Landing hero + Forecasts map + forecast card
- **Hero** (`components/hero.tsx`) — layout cloned from the reference, recolored to black & white:
  - **Top-left stacked display**, ragged-left, oversized: line 1 the grotesk wordmark **ENVISION**; line(s) below in monospace for the descriptor/coverage (e.g. `WILDFIRE · CYCLONE` / `GLOBAL · SELF-EVOLVING`). Tight leading, lots of empty space above.
  - **Lower-left micro-paragraph**, uppercase tracked-out mono, ≤2 lines — the pitch (e.g. "AN EXPERIMENTAL SELF-EVOLVING AGENT MONITORING GLOBAL WILDFIRE AND TROPICAL-CYCLONE RISK").
  - **Lower-right large mono wordmark** (the "SF.CA" slot) — pick a brand mark: `GLOBAL`, `EARTH`, or a coverage/identity token. *(Decision in §11.)*
  - **Background texture:** faint ghosted monospace behind the type — use real Envision material (a detection skill's `run(now, db)` source, or a scroll of `lat,lon,signal_type` rows) at very low opacity. Thematically richer than random code.
  - **No centerpiece graphic.** Black field only — no bloom/glow/gradient. The type, the ghost-code texture, and the negative space carry it. (A faked monochrome "heat bloom" would be decoration pretending to be data; omit it.)
  - **Scroll cue:** circled down-arrow, center-bottom (`scroll-arrow.tsx`) → smooth-scrolls to the Forecasts map section. Respect `prefers-reduced-motion` (jump, no smooth).
  - Full viewport height; the map section begins exactly one scroll down.
- **Forecasts map:** collapse to 3 toggles in `layer-state.ts` — **Forecasts** and **Detections** map to signal_type sets; **Atmosphere** gates mounting `<WindLayer/>` (leaflet-velocity, lazy-mount on enable). Defaults Forecasts+Detections ON, Atmosphere OFF; rebuild `map-layer-panel` for 3 items. Forecast + signal layers **keep their existing colors** on the dark basemap; just verify contrast and dark-style the velocity legend in `wind-layer.tsx`.
- **Forecast dropdown:** keep LLM reasoning + typing animation; **remove the skip button** (`forecast-dropdown.tsx`/`typing-text.tsx`).
- **Forecast card de-dup:** apply the §7.2 grouping in both the dropdown and `/forecast/[id]`.

### Day 3 — Evolution page (largest build)
- Layout: top ~20% = one-liner explaining the page + the **Brier/FP/Hit definitions block** (`metric-legend.tsx`, moved up from tooltips). Bottom ~80% = downward-expanding lineage tree.
- **Remove** the "Envision is an experimental, self-evolving agent system…" intro paragraph entirely.
- **Skill tree:** React Flow + dagre top→bottom layout (one chain per skill family, branches for shadow candidates). Unclicked node = one-line user-friendly description. Click → expand/dropdown with Brier (4dp, live), FP, hits, version, generation_method, sparkline (reuse `brier-sparkline`).
- **Lineage edges:** custom animated **rolling dotted line** — SVG `stroke-dasharray` + `@keyframes` on `stroke-dashoffset`. **Gate behind `prefers-reduced-motion`** (static dashes when reduced).
- Graph is a client island; data fetched server-side and serialized in.

### Day 4 — New About figure + Disclaimer + copy pass
- **About:** three connected panels **Ingest → Forecast → Evolve**. Unexpanded, they read as one coherent left-to-right pipeline (connectors between them). Click any panel → expand to detail in the format *"The [Ingest] layer is responsible for …; every [cadence], it …."* Relocate the three status facts into their matching panels (§7.3).
  - *Ingest:* pulls from public sources (FIRMS/NWS/NHC/JTWC/Open-Meteo/ECMWF/AIFS, + GDACS ground truth) on per-source cadences (30 min → 12 h); normalizes to `signals`. Shows **last ingestion**.
  - *Forecast:* detection skills read signals every cadence and emit probabilistic forecasts with LLM reasoning (cap 0.85). Shows **skills active**.
  - *Evolve:* every 24 h the curator reads Brier, mutates skill code, backtests + shadow-evaluates, queues operator-gated promotions. Shows **curator status / last proposal**.
- **Disclaimer:** trim to locked §12 text + non-goals; relocate sources/methodology to About Ingest; demote to footer.
- **Less-wordy pass** across all pages; verify NEVER-CUT items (§5) still present.
