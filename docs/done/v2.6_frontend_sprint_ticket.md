## Pre-decided

**Inherited:** Modal-only runtime; `agent/modal_skills/<id>/`; Vercel + Neon; Leaflet via dynamic-import (`ssr: false`); per-layer visibility via `LayerVisibilityContext`.

**New for v2.6:**

1. **Leaflet pane z-ordering replaces `bringToFront()` hacks.** Three explicit panes registered at map mount:
   - `signalsPane` — z-index 400, bottom (FIRMS hotspots, GDACS, point signals)
   - `polygonsPane` — z-index 500, middle (ECMWF, AIFS grid polygons)
   - `forecastsPane` — z-index 600, top (forecast markers, primary attention)
   - Wind layer (D3b) renders on the *map's* default tile pane (z-index 200), below all signals.

2. **Canvas renderer for high-density layers.** `L.canvas()` instances per dense layer (FIRMS, polygons globally). SVG (Leaflet default) chokes above ~2000 elements; Canvas scales to ~50k smoothly. Use `renderer={L.canvas()}` on the relevant React-Leaflet components.

3. **No more markercluster anywhere.** `react-leaflet-cluster` dependency removed. The "cluster blobs" UX is wrong for atmospheric/disaster monitoring where individual points matter as evidence, not as count summaries.

4. **Polygon opacity becomes zoom-dependent.** Formula: `opacity = max(0.05, 0.25 - max(0, 4 - zoom) * 0.05)`. At zoom 0–3, polygons render as soft global tint (0.05–0.20). At zoom 4+, full 0.25 opacity. Updates on every zoomend event.

5. **Wind field storage: gzipped JSON in `wind_fields.data_compressed`** (`BYTEA` column). Raw wind field at 0.25° global resolution is ~10–15 MB per cycle; gzipped to ~3 MB. 12h cadence × 14d retention = 28 rows × ~3 MB = ~85 MB. Easily inside Neon free tier.

6. **`leaflet-velocity` is the library.** Daniel Wild's Leaflet plugin, canonical for u/v wind field animation. Particle-based Canvas rendering, animated streamlines. Single dependency add to viewer.

7. **Wind layer cadence matches AIFS.** 12h cycle (00 and 12 UTC + 4h delay = 04:00, 16:00 UTC, same as existing AIFS skill). Layer toggle defaults OFF (heavy data, opt-in only).

8. **New LAYER_TREE category: "Atmospheric flow".** Houses the wind layer. Single layer for now; future continuous-field visualizations (humidity, pressure) would land here.

#### D3a-2 — AIFS skill extension

Extend `agent/modal_skills/aifs-overlay/run.py`:

- After the existing 4-signal-type extraction loop, add a `_emit_wind_field` function gated by env var `AIFS_EMIT_WIND_FIELD=true` (default on).
- Build the wind field JSON in `leaflet-velocity` format:
  ```python
  def build_wind_field(ds_u, ds_v, run_time, valid_at):
      # ds_u, ds_v are xarray DataArrays at +24h forecast horizon
      lats = ds_u.latitude.values  # descending: 90 to -90
      lons = ds_u.longitude.values  # ascending: -180 to 180 (or 0-360, normalize)
      
      header_base = {
          "parameterUnit": "m.s-1",
          "dx": float(lons[1] - lons[0]),
          "dy": float(lats[0] - lats[1]),
          "la1": float(lats[0]),
          "lo1": float(lons[0]),
          "la2": float(lats[-1]),
          "lo2": float(lons[-1]),
          "nx": len(lons),
          "ny": len(lats),
          "refTime": run_time.isoformat(),
          "forecastTime": 24,
      }
      
      return [
          {
              "header": {**header_base, "parameterCategory": 2, "parameterNumber": 2, "parameterNumberName": "U-component_of_wind"},
              "data": ds_u.values.flatten().tolist(),
          },
          {
              "header": {**header_base, "parameterCategory": 2, "parameterNumber": 3, "parameterNumberName": "V-component_of_wind"},
              "data": ds_v.values.flatten().tolist(),
          }
      ]
  ```
- Serialize to JSON, gzip with `gzip.compress(level=6)`.
- INSERT into `wind_fields` with run_time, valid_at (run_time + 24h), and the compressed payload.
- Add `psycopg[binary]` already in image; add `gzip` (stdlib, no install).

**Acceptance:** `modal run agent/modal_skills/aifs-overlay/app.py` inserts one row into `wind_fields`. Size_bytes column shows ~2–5 MB.

#### D3a-3 — API route `viewer/app/api/wind/route.ts`

```ts
export async function GET(request: Request) {
  // Fetch most recent wind_field
  // Decompress + parse JSON
  // Return as application/json with appropriate cache headers
}
```

- Query: `SELECT data_compressed FROM wind_fields ORDER BY valid_at DESC LIMIT 1`.
- Decompress via Node `zlib.gunzipSync()`.
- Cache headers: `Cache-Control: public, max-age=21600, stale-while-revalidate=43200` (6h fresh, 12h stale-allowed — wind data changes only twice daily).
- Content-Encoding: gzip if you want to skip Node decompression and pass through gzipped bytes (faster, smaller payload, browser decompresses). Cleaner but trickier headers.

**Acceptance:** `curl https://<vercel-url>/api/wind` returns valid JSON in `leaflet-velocity` format.

#### D3b — Wind layer integration

Net-new `viewer/components/wind-layer.tsx`:

```tsx
'use client'
import 'leaflet-velocity'
import 'leaflet-velocity/dist/leaflet-velocity.css'
import { useEffect, useState } from 'react'
import { useMap } from 'react-leaflet'

export function WindLayer() {
  const [data, setData] = useState<any | null>(null)
  const map = useMap()
  
  useEffect(() => {
    fetch('/api/wind')
      .then(r => r.json())
      .then(setData)
  }, [])
  
  useEffect(() => {
    if (!data) return
    const velocityLayer = (L as any).velocityLayer({
      displayValues: true,
      displayOptions: {
        velocityType: 'Wind',
        position: 'bottomleft',
        emptyString: 'No wind data',
        speedUnit: 'm/s',
      },
      data,
      maxVelocity: 30,
      velocityScale: 0.01,
      particleAge: 90,
      lineWidth: 1.5,
      particleMultiplier: 1 / 200,
      colorScale: [
        'rgb(36,104,180)', 'rgb(60,157,194)', 'rgb(128,205,193)',
        'rgb(151,218,168)', 'rgb(198,231,181)', 'rgb(238,247,217)',
        'rgb(255,238,159)', 'rgb(252,217,125)', 'rgb(255,182,100)',
        'rgb(252,150,75)', 'rgb(250,112,52)', 'rgb(245,64,32)',
      ],
    })
    velocityLayer.addTo(map)
    return () => { map.removeLayer(velocityLayer) }
  }, [data, map])
  
  return null
}
```

Install dependency: `npm install leaflet-velocity`. TypeScript types are imperfect; `as any` for `L.velocityLayer` is the path of least resistance.

## Notes / gotchas

- **Pane registration order matters.** Panes must be created BEFORE any layer is added that references them. The `useEffect` in `forecast-map-impl.tsx` runs after map mount but before child layers' first render — verify the timing. If a layer tries to use `pane="signalsPane"` before the pane exists, Leaflet falls back to the default pane silently.
- **Canvas vs SVG renderers are per-layer, not per-map.** You can mix: FIRMS on Canvas, NHC on SVG. Canvas is faster but doesn't support all SVG features (gradients, complex shapes). Plain `<CircleMarker>` on Canvas works fine.
- **`leaflet-velocity` and React-Leaflet's strict mode.** Velocity layer mutates Leaflet state directly. Cleanup in `useEffect` return must remove the layer or it persists on hot reload.
- **Wind layer color scale** in the snippet matches earth.nullschool's traditional palette. The CartoDB Positron base tile is light, so the wind colors need decent contrast — verify visually after first deploy.
- **AIFS wind grid orientation.** ECMWF data ships with latitude descending (90 → -90) and longitude either -180→180 or 0→360 depending on the variable. `leaflet-velocity` expects la1 > la2 (north to south) and lo1 < lo2 (west to east), with longitude in -180→180. Normalize during JSON construction.
- **Gzipped payload size.** First implementation: serialize JSON, then `gzip.compress(json_bytes, compresslevel=6)`. Verify size_bytes < 5 MB after compression. If >5 MB, drop precision (round floats to 2 decimals) or subsample the grid (every other lat/lon point — halves resolution, quarters data).
- **`/api/wind` cold start on Vercel.** Decompressing 3 MB gzip + serializing back to JSON on every cache miss is non-trivial. Consider passing the gzipped bytes through with `Content-Encoding: gzip` header — browser handles decompression natively, Vercel just streams bytes. Lighter cold start.
- **`leaflet-velocity` performance at high particle counts.** `particleMultiplier: 1/200` is reasonable. Below 1/100 (more particles) starts to lag on mid-range laptops. Tune in development.
