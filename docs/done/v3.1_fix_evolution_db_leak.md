# v3.1 — Fix Ticket: `/evolution` crashes with "DATABASE_URL is not set in the environment"

**Type:** bug fix · `viewer/` only · no backend/DB/env change
**Related:** `v3.1_day2_ticket.md` Task 1 (Evolution page). Apply this before continuing Day 2.

---

## Symptom
Loading `/evolution` throws a runtime error:

```
Runtime Error
DATABASE_URL is not set in the environment
lib/db.ts (4:9) @ module evaluation
```

`lib/db.ts` fails its top-level guard (`if (!process.env.DATABASE_URL) throw …`) at **module-evaluation** time.

## Diagnosis — already confirmed, do NOT chase env config
- `/` (Forecasts) loads cleanly and queries the DB fine → `DATABASE_URL` **is** set for the server runtime. **This is not a missing-env-var problem.** Do not edit `.env.local`, Vercel env, or `db.ts`'s guard.
- The error is **only** on `/evolution`, the page that just gained a `'use client'` React Flow island.
- **Root cause:** a client module in the evolution subtree imports from `lib/lineage-queries.ts` (or `lib/db.ts`) with a **value import**, so the bundler pulls the whole transitive graph — including `db.ts` — into the **client** bundle. On the client `process.env.DATABASE_URL` is undefined, so `db.ts`'s top-level throw fires as "module evaluation." A type-only import would be erased at compile time; a value import is not.

## Locate the leak
```bash
grep -rln "'use client'" viewer/components viewer/app/evolution
grep -rn "lineage-queries\|/lib/db\|from '@/lib/db'" viewer/components viewer/app/evolution
```
The offending file appears in **both** lists — typically the tree/node/edge component doing `import { SomeType } from '@/lib/lineage-queries'` (value import of a type) or importing a query helper/const.

## Fix
1. **Create `lib/lineage-types.ts`** — pure TypeScript interfaces only (`LineageNode`, `LineageEdge`, per-node stats shape, etc.). **No import of `db`, `lineage-queries`, or any server module.**
2. **`lib/lineage-queries.ts`** — add `import 'server-only';` as the very first line. Import its types from `./lineage-types`. Export only the async fetchers (e.g. `getLineage()`).
3. **`lib/db.ts`** — add `import 'server-only';` as the first line. (Leave the `DATABASE_URL` guard as-is.) This converts any *future* client-side import of the DB layer into an explicit build-time "server-only module in client component" error instead of this same cryptic env throw on some other page.
4. **Client island** (`skill-tree.tsx` and any custom node/edge components) — import shared types via `import type { LineageNode } from '@/lib/lineage-types'` only; import **nothing** from `lineage-queries` or `db`. Receive all data as **props**.
5. **`app/evolution/page.tsx`** — must be a **server component** (no `'use client'`): `const data = await getLineage();` then render `<SkillTree data={data} />`, passing plain serialized data down.

> Quick-green shortcut if you want the page up first: change the single offending `import {…}` to `import type {…}`; it usually clears immediately. Still do steps 1–5 for the durable fix.

## Out of scope
- Do **not** add `server-only` to `lib/queries.ts` or touch the Forecasts (`/`) path — it works and is not part of this bug.
- No env, migration, or agent changes.
