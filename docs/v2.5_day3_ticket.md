#### B4 — `viewer/components/typing-text.tsx`

Generic typing-animation component. Reusable beyond the forecast dropdown.

```tsx
type TypingTextProps = {
  text: string
  charsPerSecond?: number  // default 30
  showCursor?: boolean      // default true
  onComplete?: () => void
}

export function TypingText({ text, charsPerSecond = 30, showCursor = true, onComplete }: TypingTextProps) {
  const [displayedChars, setDisplayedChars] = useState(0)
  const [done, setDone] = useState(false)
  
  useEffect(() => {
    if (displayedChars >= text.length) {
      setDone(true)
      onComplete?.()
      return
    }
    const interval = setInterval(() => {
      setDisplayedChars(c => Math.min(c + 1, text.length))
    }, 1000 / charsPerSecond)
    return () => clearInterval(interval)
  }, [displayedChars, text.length, charsPerSecond, onComplete])
  
  return (
    <span>
      {text.slice(0, displayedChars)}
      {showCursor && !done && <span className="animate-pulse">▊</span>}
    </span>
  )
}
```

Plus a "skip to end" affordance: parent component passes `displayedChars` state down if it wants to control the skip externally; or expose a ref-forwarded `complete()` method. Lean: simple pattern — wrap `TypingText` in a parent that holds an "instantly complete" override prop.

## Notes / gotchas

**Track A:**

- **LLM API costs scale with forecast volume.** Per Track A: each new forecast triggers a Sonnet call. At v2 substrate scale (~30–100 forecasts/day from all 4 skills combined), cost is ~$3–8/month. If volume spikes (fire-active season globally), monitor and consider falling back to Haiku for the explainer.
- **API failure fallback is load-bearing.** The LLM call MUST have a try/except wrapping it. If Anthropic API is down or returns an error, store the templated fallback string in `forecasts.reasoning` and continue. Never let LLM unavailability block a forecast emission.
- **Prompt template variables come from trace data.** TraceBuilder's `.inputs` and `.intermediate` dicts are the canonical source. Don't recompute values for the prompt — read from what the trace already records.
- **`wildfire-risk-elevated` generalization may quiet down US output briefly.** If ECMWF fire weather grid polygons cover the western US AND overlap with NWS fire warnings, the OR-union doesn't change US behavior. But if the queries dedupe poorly (same cluster intersecting both), you might see double-counting. Monitor first run; tune if needed.
- **Hermes archival is non-destructive.** Renaming `~/.hermes/skills/` to `.archive.<date>` preserves the directory; you can always restore. Don't `rm -rf`.
- **`agent/skills/` becomes read-only docs.** After archival, the directory is reference material — useful for v3's mutator to read prior versions, useful for human review of skill lineage. Don't delete from repo.
- **`~/.hermes/.env` stays in place.** Hermes itself can be uninstalled later if you want, but the file is harmless and contains keys you may still want for non-Modal scripts.

**Track B:**

- **Polygon volume can be substantial.** Global ECMWF + AIFS fire weather grid polygons can total 50–200 per cycle. At any time, ~1000 active polygons might be present across both sources. Bbox-filtering in the API route keeps this manageable per view, but a "show all globally" view at zoom 4 may pull many. The 5000-point cap from Day 2 applies to polygons too.
- **Polygon click behavior.** Polygons are clickable in Leaflet by default. Make sure clicking a polygon opens a SMALL popup (not the full forecast dropdown — that's for forecasts only). Polygons are signal data; their popup is "what kind of polygon, what's in the payload."
- **Forecast marker click vs polygon click.** Both are clickable; Leaflet usually picks the topmost layer. Verify that clicking on a forecast marker that sits inside a polygon opens the FORECAST dropdown, not the polygon popup. May need `bringToFront()` on the forecast markers' layer.
- **`forecasts.reasoning` may be empty for old forecasts.** Pre-Track A forecasts have templated reasoning; post-Track A have LLM-generated. The dropdown should handle both gracefully — if reasoning is empty, show "(no reasoning available)" rather than empty typing animation.
- **Typing speed tuning.** 30 chars/second is comfortable reading speed. If operators find it slow, increase to 50. If too fast, drop to 20. Make `charsPerSecond` configurable.
